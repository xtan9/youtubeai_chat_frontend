# Site UAT — October 22, 2026

Baseline: `fb18ce29824ffcad939033fafbefc7a4097ee440` on `main`.
Scope: existing user journeys, public desktop exploration, Chromium desktop/mobile
fixture journeys, production synthetic-account smoke, and isolated Stripe Sandbox
checkout. This is a bug-fix pass; no new product behavior or entitlement policy was
introduced.

## Confirmed defects and fixes

| Defect | Reproduction | Correction |
| --- | --- | --- |
| Bare Summary page has no input | Open `/summary`; it asks for a URL but only shows empty result tabs | Reuse the existing URL form and mount results after submission |
| Authentication loses destination | Choose monthly/yearly on Pricing, then switch Sign up → Login | Preserve normalized internal return destinations across auth links and password/Google login |
| Summary limit login loses video | Open a Summary limit wall and choose “I have an account” | Preserve the supplied Summary return destination |
| Stale input error | Submit an invalid URL, then clear or edit it | Clear the obsolete error when input changes |
| Misleading free-plan wording | Anonymous limit wall promises “unlimited free”; Summary page promises no paywall | State the existing one-summary trial and ten-summary monthly Free limit |
| Incorrect FAQ retention/model claims | Privacy FAQ says transcripts are discarded; accuracy FAQ names a retired provider | Describe existing cached transcripts/summaries and gateway processing without unsupported retention/provider promises |
| Changing policy revision dates | Reload Terms/Privacy on a different day | Show stable dates from their last substantive source revisions |
| Production/payment browser setup fails | Playwright 1.59.1 rejects `ubuntu26.04-x64` selected by `ubuntu-latest` | Pin browser jobs to supported Ubuntu 24.04 |
| Project production smoke silently skips | Project step lacks its dedicated live-summary account credentials | Supply credentials only to that step and fail explicitly on missing configuration |

Password recovery still returns home after success, as required by its existing
session-policy contract. This pass preserves the return destination on its Login
link without changing recovery/session revocation semantics.
