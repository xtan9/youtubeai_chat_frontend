# Continue Learning architecture contract (Issue #346)

The first Continue Learning release uses the existing public Video Catalog and
Postgres-hosted asynchronous work. An admitted public Video may receive one
server-validated structured Semantic Profile per profile schema and evidence
fingerprint. The implementation is defined in
`docs/specs/2026-08-11-structured-semantic-profile-contract.md` and ADR 0007.

The Profile is generated by the existing server-only `LLM_GATEWAY_*` path and
is never generated in a learner request. Candidate retrieval is deterministic
Postgres concept overlap with a private service-role RPC. A later asynchronous
assessment may call the same Gateway for the bounded candidate pool. No
provider-specific embedding key, pgvector index, second datastore, external
queue, live discovery request, learner personalization, or browser access to
Profile/evidence is part of the first release.

The required pre-pilot evidence is a fixed multilingual Gateway evaluation:
strict schema validity, cross-language concept normalization, useful-neighbor
recall, false-neighbor rejection, all Continuation Relationships, latency,
cost, retries/dead letters, and representative source coverage. Human review
and the existing rollout gates remain mandatory; no benchmark automatically
activates a model or exposes Continue Learning.

Downstream issues retain their dependency order: #349 profile generation and
retrieval contract, #350 deterministic candidate pairs and learner-unlinked
Discovery Demand, #351 assessment, #352–#356 rollout/UI/analytics slices, and
#357 integrated pilot evidence.
